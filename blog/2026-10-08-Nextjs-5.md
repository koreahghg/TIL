## **시작하며**

React를 공부하고 프로젝트를 진행하다 보면 Next.js라는 기술을 자연스럽게 접하게 되는데요.

처음에는 React만으로도 페이지를 만들고 API를 연결할 수 있는데 굳이 Next.js를 사용하는 이유가 무엇인지 궁금했습니다.

특히 app 디렉토리나 page.tsx, layout.tsx, Server Component, Client Component 같은 새로운 개념이 등장하면서 React와는 조금 다른 방식으로 프로젝트가 구성된다는 것을 알게 되었습니다.

그래서 Next.js가 무엇인지부터 프로젝트 구조와 Routing, Server Component와 Client Component까지 공부하면서 알게 된 기본적인 내용을 정리해보려고 합니다.

## **Next.js란?**

### Next.js란?

Next.js는 React를 기반으로 웹 애플리케이션을 만들 수 있도록 여러 기능을 제공하는 프레임워크입니다.

React를 사용하면 컴포넌트를 만들고 화면을 구성할 수 있지만, 실제 프로젝트에서는 페이지 이동이나 프로젝트 구조, 서버에서 데이터를 처리하는 등의 기능도 필요합니다.

Next.js에서는 이런 기능들을 하나의 프레임워크 안에서 사용할 수 있습니다.

특히 현재 Next.js의 App Router는 파일 시스템을 기반으로 Routing을 구성하며, Server Component와 같은 React의 기능을 함께 사용할 수 있습니다.

### React와 Next.js의 차이

React는 UI를 만들기 위한 라이브러리이기 때문에 필요한 기능을 다른 라이브러리와 함께 구성하는 경우가 많습니다.

반면 Next.js는 React를 기반으로 Routing, 페이지와 Layout 구성, 서버와 클라이언트에서 컴포넌트를 사용하는 방식 등 웹 애플리케이션을 만들 때 필요한 기능들을 함께 제공합니다.

처음에는 React와 Next.js가 비슷해 보여서 차이를 잘 이해하지 못했는데, 프로젝트를 만들어보면서 Next.js가 React를 기반으로 프로젝트를 구성하기 편하게 만들어주는 프레임워크라는 것을 알게 되었습니다.

## **프로젝트 구조와 Routing**

Next.js에서 가장 먼저 눈에 들어왔던 부분은 app 디렉토리였습니다.

App Router에서는 폴더와 파일 구조를 이용해 페이지와 Routing을 구성할 수 있습니다.

예를 들어 다음과 같이 구성할 수 있습니다.

```
app
├── page.tsx
├── layout.tsx
└── about
    └── page.tsx
```

이 경우 app/page.tsx는 기본 페이지가 되고,

app/about/page.tsx는 /about 경로의 페이지가 됩니다.

즉, 폴더를 만들고 그 안에 page.tsx를 작성하는 방식으로 새로운 페이지를 만들 수 있습니다

### Link

페이지를 이동할 때는 Next.js에서 제공하는 Link를 사용할 수 있습니다.

```
import Link from 'next/link'

export default function Home() {
  return (
    <Link href="/about">
      About
    </Link>
  )
}
```

Link를 사용하면 Next.js의 클라이언트 측 Navigation 기능을 활용할 수 있습니다.

처음에는 React에서 react-router 같은 라이브러리를 사용해서 Routing을 구성했던 것과 비교했을 때, 폴더와 파일을 이용해 페이지를 구성할 수 있다는 점이 편리하게 느껴졌습니다.

## **Server Component와 Client Component**

Next.js를 공부하면서 가장 헷갈렸던 부분 중 하나가 Server Component와 Client Component였습니다.

App Router에서는 기본적으로 page와 layout이 Server Component로 동작합니다.

그리고 상태나 이벤트, 브라우저 API처럼 클라이언트에서 동작해야 하는 기능이 필요한 경우 Client Component를 사용할 수 있습니다.

### Server Component

Server Component는 서버에서 렌더링되는 컴포넌트입니다.

예를 들어 서버에서 데이터를 가져와 화면에 보여주는 작업 등에 사용할 수 있습니다.

```
export default async function Page() {
  const data = await fetchData()

  return <div>{data.title}</div>
}
```

공식 문서에서는 Server Component를 데이터 가져오기, 서버에 가까운 곳에서 데이터 처리하기, 클라이언트로 보내는 JavaScript 양을 줄이는 등의 경우에 사용할 수 있다고 설명하고 있습니다.

### Client Component

반대로 사용자의 클릭이나 입력처럼 브라우저에서 동작해야 하는 기능이 있다면 Client Component를 사용할 수 있습니다.

이때 파일의 가장 위에 "use client"를 작성합니다.

```
'use client'

import { useState } from 'react'

export default function Counter() {
  const [count, setCount] = useState(0)

  return (
    <button onClick={() => setCount(count + 1)}>
      {count}
    </button>
  )
}
```

"use client"는 해당 파일을 Client Component의 시작점으로 지정하는 역할을 합니다.

useState, 이벤트 핸들러, 브라우저 API 등이 필요한 경우 사용할 수 있습니다.

처음에는 "use client"를 거의 모든 컴포넌트에 작성해야 하는 것이라고 생각했는데, 실제로는 필요한 컴포넌트에만 사용하면 된다는 것을 알게 되었습니다.

### 마치며

Next.js를 공부해보면서 React를 사용하는 것과는 또 다른 방식으로 웹 프로젝트를 구성할 수 있다는 것을 알게 되었습니다.

처음에는 app 디렉토리나 Server Component, Client Component 같은 개념이 낯설었지만 직접 프로젝트에 적용해보면서 각각 어떤 역할을 하는지 조금씩 이해할 수 있었습니다.
